### 与维护者沟通（先沟通再写代码）

2. 提议的解决方向（只说方向，不说全部细节）
3. 询问是否有兴趣接受这类 PR、是否已有计划

## 二、代码实现

### 实现前的准备（未完成禁止写代码）

1. 阅读所有需要修改的文件，理解当前实现
2. 检查代码风格规范：有无 .eslintrc / pyproject.toml / ruff.toml？命名风格（snake_case / camelCase）？注释和 docstring 习惯？类型标注完整程度？
3. 确认主分支可正常运行（跑通 README quickstart 或现有测试）

### 实现原则

- **逐步实现，每步可验证**：严格按实现步骤顺序，每完成一步项目必须仍可运行
- **最小侵入性**：优先扩展而不是修改现有函数；必须修改时只改必须改的部分；新增公共接口保持向后兼容
- **风格一致性**：命名、注释、类型标注与现有代码一致；不引入项目未使用的新依赖，除非确实必要

### 实现流程

1. **Step 1 接口定义**：先只定义核心接口/类签名/函数签名（函数体用 `pass` 或 `raise NotImplementedError`），停下来输出接口清单与衔接方式，确认后再继续
2. **Step 2 核心逻辑实现**：逐文件完成，每个文件输出"实现了什么、与方案有无偏差及原因"
3. **Step 3 集成**：接入现有调用链，检查原有用法仍有效、新功能触发路径完整、错误处理无遗漏
4. **Step 4 验证**：最小可运行 demo + 单测（happy path / 边界情况 / 兼容性），测试文件放在项目现有测试目录、命名风格一致

### 遇到以下情况停下来询问用户，不自行决定

- 方案有遗漏，需要改动超出预定范围的文件
- 与现有代码冲突，无法在不破坏兼容性的前提下实现
- 两种实现方式各有利弊，需要人工决策
- 需要引入新的第三方依赖

## 三、PR 提交

### Commit 拆分

按逻辑拆分为 2~4 个 commit，每个 commit 只做一件事，遵循 Conventional Commits：

```
{type}({scope}): {描述}
# type: feat / fix / refactor / test / docs / chore
```

### PR 描述模板

- **标题：** `{type}({scope}): {一句话描述}`
- **Problem**：描述当前存在的问题（客观陈述，不带情绪）
- **Solution**：本 PR 的解决思路，以及为什么选择这个方案
- **Changes**：新增/修改了什么
- **Testing**：如何验证改动有效、测试覆盖了哪些场景
- **Notes for Reviewer**：需要 reviewer 重点关注的地方，或有意为之的设计决策

### 提交后跟进

- 时常关注维护者的 review 意见，及时响应（数日内）
- 超过 1~2 周无回应可礼貌跟进（评论或邮件），不要催促
- Review 意见逐条回应，修改后说明改动点

## 四、面试叙事框架（STAR 六要素）

- **背景（Context）**：项目是什么？在 AI Agent 领域解决什么问题？为什么选择给它做贡献？发现了什么架构层面的缺失？
- **我做了什么（Contribution）**：一句话说清楚贡献；改动在项目中的位置、影响哪些使用路径
- **我怎么分步做的（Process）**：3~5 个关键步骤，每步聚焦"我做了什么决定"而非"我写了什么代码"
- **成果（Result）**：PR 状态（已合并/审核中，附链接）、对项目的影响、可量化指标（如 token 减少 X%、响应时间降低）、维护者反馈（直接引用 review 评论关键句）
- **遇到的困难（Challenges）**：1~2 个真实技术卡点，格式为"困难描述 → 排查解决过程 → 结论"。这部分最有区分度，要具体
- **下次怎么优化（Reflection）**：技术层面（更优雅的实现）、流程层面（沟通时机、PR 拆分）、范围层面（不必要的改动或遗漏的边界）

最后列出**能体现的 2~3 条核心能力**，对应面试考察维度。

## 五、60 秒面试话术（可选，用户需要时生成）

在 STAR 六要素基础上，压缩生成一段可直接背诵的"面试实战话术（60 秒版）"：

- 第一人称、项目口吻，按 2~4 个层次完整串联：方案背景 → 关键技术决策 → 风险兜底
- 风格：术语在前、人话紧跟、中文口语化、编号化，结尾附一句记忆口诀
- 时长控制在正常语速 60 秒以内（约 250~300 字）
- 内容必须与 STAR 六要素一致，不新增未发生的细节

示例结构：
> "我在给 {项目} 做贡献时发现 {问题}。我的方案是 {一句话方案}：第一，{关键决策 1}；第二，{关键决策 2}；风险上我通过 {兜底手段} 保证兼容性。最终 PR 被合并，{可量化成果}。一句话记住：{记忆口诀}。"
